# Recorded action lineage contract

`readActionLineage(siteId, actionId)` returns the typed `ActionLineage` view and uses a site-scoped action lookup; absent or other-site actions raise the existing 404 `ResearchServiceError`. `projectActionLineage(input, sourceRows?, bounds?)` is the pure typed projection. The public DTOs and projection input types are exported from `lib/pipeline/lineage-types.ts`.

Only supported local targets are emitted: action detail at `/sites/:siteId/actions/:actionId`, research run detail at `/sites/:siteId/research/runs/:runId`, and safe external HTTP(S) source URLs. Internal path identifiers are restricted to alphanumeric, underscore and hyphen segments. Historical business, finding, draft and agent-attempt nodes have no exact-detail link. Delivery/verification/measurement nodes link to their containing action detail, not a fictional receipt route; consumers must not describe that link as an exact receipt or verifier view.

`lib/research/crawl-actions.ts` persists the explicit producer fields `knowledge_document_id` and `knowledge_revision`. A valid identifier and positive integer revision produce a recorded pin node with `referenceOnly: true`, not a resolved/confirmed historical document. Its link remains null until a historical revision view exists. Malformed/absent pins remain `not_recorded`. Do not accept guessed field names, infer a historical input from later `QuestionCoverage`, or substitute the current accepted revision. No schema extension is part of this task.

Research runs must match the action's recorded run ID and both site and project. The source query selects only IDs from `sourceIdsForAction` and constrains the related run by that same site/project; projection checks the citation and run ID again. No matching by query, URL, or date occurs. Drafts and agent attempts are relation children and are also filtered by `siteId`. Delivery has no `siteId` field in Prisma and is included only through the action's `deliveries` relation.

Lists disclose `{ returned, limit, hasMore }` for drafts, agent attempts, receipts and sources. Reads ask for one beyond each cap to report truncation. Limits are 100 drafts, 100 agent attempts, 20 receipts and 200 sources. Timestamps are safely normalized; invalid legacy dates become `null`. Approval/delivery/verification/measurement records remain separate. A verification timestamp does not establish a passing verifier result, and an outcome measurement does not establish causal impact. Provider error/prompt/credential fields are not selected or projected. Reads perform no writes or provider calls.
