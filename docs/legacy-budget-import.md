# Protected historical budget import

`POST /api/internal/budget-imports` is an internal, operator-controlled migration endpoint. It requires `Authorization: Bearer $HELLOADA_PROVISIONING_TOKEN` and returns `Cache-Control: no-store` on every response. `GET /api/internal/budget-imports?receiptId=...` uses the same authorization and returns the persisted audit snapshot for a completed import.

Pause any active source policy through the separate protected compare-and-set endpoint before importing. `POST /api/internal/budget-imports/source-freeze` accepts `mode: "freeze-source-plan"` to return the exact `sourcePolicyHash`; after reviewing it, send `mode: "freeze-source-apply"` with that hash, source and target site/project pins, target HelloAda binding generation, an idempotency key, and a reason. Apply verifies both project identities and binding, rejects active source executors or in-flight research runs, disables only the source `SeoResearchPolicy.enabled` and `articleResearchEnabled` flags, and disables `ResearchPolicy.enabled` while incrementing its revision (creating a disabled row if none exists). It writes an immutable freeze receipt with before and after policy snapshots in the same transaction. Dispatch request and worker paths lock and recheck these policy rows before creating queued work or marking a provider run active. `GET /api/internal/budget-imports/source-freeze?receiptId=...` reads that distinct receipt. The freeze does not change research budget allowances or create provider calls.

`node --env-file=<private-test-env-file> --import tsx scripts/test-legacy-budget-import-db.ts` runs the schema migrations and PostgreSQL integrity checks in a randomly named temporary schema, then drops only that schema. The database role must be allowed to create schemas.

The operator supplies the exact old source project/site IDs, the new target site ID, its expected HelloAda binding generation, a stable import idempotency key, and the legacy reservation rows. Each row identifies the SiteAgent reservation and exact CrawlSEO `ArticleKeywordResearchRun` ID, the claimed operation and legacy status, period/timezone/currency/quote, and source reservation timestamps. The server derives provider task status, provider task ID, and actual cost from the source run table. It verifies that each task belongs to the declared old site and project, the sites share the same domain and external project identity, the old project has no active connector binding, the target is active with the exact HelloAda generation, the operation matches the DataForSEO run kind, and all costs are USD.

Use `mode: "plan"` first. The response contains the server-computed `sourceEvidenceHash`, exact source/target mapping, and the effective imported values for every row. Review that response before submitting `mode: "apply"` with the same mapping, rows, idempotency key, and `expectedSourceEvidenceHash`. Apply recomputes all source records under a serializable transaction and commits every budget row plus an immutable import receipt together. A stale hash, changed mapping, changed source task, or reused idempotency key with different data fails without partial import.

A source task with an explicit DataForSEO cost receipt is imported as `SETTLED` only after its source run is terminal (`COMPLETED` or `FAILED`). A nonterminal task with a partial cost remains `UNCERTAIN` at its full quote with no actual cost recorded. A failed task with no cost receipt is also `UNCERTAIN`; the import does not invent a zero actual cost. A never-attempted request remains `RESERVED` only when the legacy ledger says it was reserved; a safe pre-dispatch release remains `RELEASED`. The source SEO and article research policies must already be paused. The import does not change allowance, currency, timezone, research settings, or dispatch jobs. The immutable receipt stores source evidence, supplied legacy rows, effective ledger values, and exact source/target binding identity for later verification.
